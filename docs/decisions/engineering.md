# Speed, reliability, apps and the bug-sweep rules

Owner decisions for this area, moved word for word out of CLAUDE.md on 21 Nov 2026.
They carry the same weight as CLAUDE.md: read this file before you change anything in this area,
and when the owner gives a new standing instruction here, add it below and its title to the index in CLAUDE.md.

- **The browser smoke test is a CI job** (`browser` in `ci.yml`, `e2e/smoke.mjs`): a real Chromium on the built app signs a fresh studio in, opens every menu page (fails on a page error, the "Couldn't show" box or a page with no heading), adds a client and checks the plan buttons. A new menu page joins its `PAGES`.

- **Backups prove themselves weekly.** `backup.sh` counts key tables at dump time and, on Sundays, restores the newest dump into a scratch database (`backup.sh drill`) and checks every table came back; a failed drill makes the backup container unhealthy until one passes. `/health` already checks the database and reports the version.

- **The apps are the live site in a window** (owner, 16 Oct: "everything that we have ... has to come into the app"; APK and installers shared by hand, never a store). `native/desktop` is Electron for Windows, Mac and Linux; `native/android` is a Trusted Web Activity in Chrome, built by `build.sh` with the SDK's own tools (no Gradle). Both open `https://studioautopilot.in`, so a feature belongs in `apps/web` and reaches every app on its next launch -- never build a feature into `native/`. The desktop shell routes links (`src/links.cjs`): our pages stay in, Facebook/Google sign-in opens an in-app popup, WhatsApp/mail/tel/other sites go out; `window.open('')` tabs stay hidden until their first address. A page can tell it is in the desktop app by `window.studioAutopilotDesktop`. Android stays full screen only while `apps/web/public/.well-known/assetlinks.json` carries the release key's SHA-256 (`02:DD:FA:...:82:67`); the key itself is the owner's, never committed. `.github/workflows/apps.yml` builds all four on a push (not to main) touching `native/` and on an `apps-v*` tag (with a Release); `docs/apps.md` is the install guide.

- **Bug sweep rules (6 Nov, 0294).** **An inbox is proven only by the confirmation link, a password reset or Google** (`auth.users.email_proven_at`, `markInboxProven` in `modules/auth/router.ts`); `email_verified` is set by a studio on any team login it makes, so it never proves a mailbox. Joining a pending invitation (`join_invitation_as`, `/auth/pending-invite`) and becoming a platform admin (`claim_platform_admin`) need the proof, and a Google sign-in onto a login whose inbox was never proven clears the password a studio set and ends its sessions. **An amount typed by a person goes through `parseAmount`** (`shared/money/parse-amount.ts`): "1,50,000" and "₹ 15,000" are numbers, never `Number(v)` (which made them ₹0). **A shoot's crew moves with it**: changing its date or start shifts the booked slots by the same amount (409 on a clash), cancelling it releases them, and deleting a project releases its bookings first. **Payments received counts an invoice's open balance even when the project's value is paid** (GST on top) and invoices on cancelled projects, so Home, Payments and Invoices agree. **Ids from another studio are refused by the database** on invoices and crew bookings (`invoices_same_company`, `team_slots_same_company`), and money on an invoice moves with it to another project. A crew payout locks its booking, cannot be set below what is paid, and a payment can be undone once. A repeat Facebook or web lead from a number whose lead is still open is a note "Enquired again" on it; from a lost, booked or archived lead it is a new lead (`capture_lead`), and a Facebook `leadgen_id` already imported is skipped. Work in review with no stage reads "final checks" to the client, never ready; an editor cannot mark work Delivered without a team stage. A Project Manager sees no crew pay in `/allocation` and no money in the client-page preview. Browser storage at the app's root is read through a guard that never throws. A draft of Create project is kept per person and studio (`setDraftScope`).

- **Speed rules (audit, 11 Nov: "tabs are opening a bit late").** The API answers the browser's permission check once per 2 hours (`maxAge` in the CORS middleware), and a GET carries no `Content-Type`. Built files under `/assets/*` are cached for a year (`public/_headers`; index.html is still checked every time). The router preloads a page's file on hover (`defaultPreload: 'intent'`) and a hot page may start its data then too (a route `loader` calling `getQueryClient()?.prefetchQuery`, as `/projects/$id` does with `projectQuery`). Queries are fresh for 30 s and kept 30 minutes by default (`main.tsx`). React, TanStack, zod and Sentry are their own chunks (`vite.config.ts`), so a deploy re-downloads only our code. **A dialog or panel the shell opens on a click is `lazy()`** (New menu's dialogs, the assistant, Suggest a feature) -- never a static import into `AppShell` or the header. **A new RLS policy writes its helpers as `(select get_current_company_id())`, `(select auth.uid())` and so on** (0302: evaluated once per query, not per row), except a plain policy on a table another policy reads in a sub-query (task_assignees, tasks, projects, clients, crm_leads, crm_automation_rules), where a sub-query would trip Postgres's recursion guard. Big card lists memo their card (`DealCard`) and pass steady handlers. The "New" badge reads `/galleries?quick=1` (our rows, no Frameline call). The VPS is a Hostinger KVM 4 in **Mumbai** (4 cores, 16 GB RAM, shared with other Coolify projects; owner, 12 Nov), so Postgres runs with `shared_buffers=2GB`, `effective_cache_size=8GB`, `work_mem=16MB`, `random_page_cost=1.1`, `shm_size: 256mb` (`docker-compose.yml`); the pool is 20. **A list sends what its screen shows, never the studio's history** (12 Nov): Leads loads open leads as light cards (`GET /crm/leads?outcome=open&shape=card`, `crmLeadCard`, `notes_preview`), booked/lost and archived only when a view asks; the drawer reads its own lead (`GET /crm/leads/:id`, `LeadDrawerById`); stage counts and the pipeline line come from `GET /crm/leads/summary`; a board column draws 30 cards, then **Show N more**. Tasks loads open tasks plus 30 days of done ones (`done_since`, descriptions cut to 200 with `description_truncated`), **Show older done tasks** pages back (`done_before`, 50 at a time), and a task's drawer or edit reads `GET /tasks/:id`. Shoots lists take a window (`from`/`to`: Team Booking the month in view, the dashboard this week) and one shoot is `GET /shoots/:id`. Pickers search on the server (`LeadPicker`, `TaskPicker`, `ShootPicker`). 0303 wraps tasks' remaining policies too: tasks already had a sub-query policy, so the recursion guard does not apply to it. **A page opened once opens at once, every time after** (owner, 12 Nov: "it should be just click, and it should come up, like when you open up a folder on a laptop"): the query cache is kept on the device in IndexedDB (`shared/api/persist-cache.ts`: per person and studio, `setCacheScope` on session, `forgetCache` on sign-out and Switch studio, a week at most, never `auth`/`assistant`/`calendar` keys or anything named token, kept across releases until `CACHE_FORMAT` in `persist-cache.ts` is bumped by hand -- bump it when a cached answer's shape changes incompatibly; a page that crashes within 15 s of a restore forgets the cache and reloads once, `forgetCacheAfterCrash`; polling queries never trigger a save) and put back before the first render (`restoreCache`, 0.4 s at most), so a page draws from it and refreshes behind; and after sign-in every menu page's file (hub tabs too) is preloaded while the app is idle, one every 300 ms, skipped on Save-Data or 2G (`useWarmPages`, `shared/layout/warm-pages.ts`). A new query key that holds a secret must start with one of those words or carry "token" in it.
